## Overview

Folder Gallery is a Node.js CLI tool that creates dynamic, web-based image galleries from directories. It generates all UI at runtime (no static HTML templates), spawns a detached background server, and provides real-time thumbnail generation with viewport-aware prioritization.

## Essential Commands

### Development
```bash
# Run tests (always run before/after changes)
npm test

# Run specific test file
npm test -- tests/gallery-utils.test.js

# Run tests in watch mode
npm run test:watch

# Run tests with coverage
npm run test:coverage

# Link local version for testing
npm run link

# Unlink when done
npm run unlink

# Start server with file watching (dev mode)
npm run dev
```

### CLI Commands (after linking)
```bash
# Start gallery in current directory
gallery up

# Start gallery in specific directory
gallery up -d /path/to/images

# Use custom port
gallery up --port 8080

# Stop all running galleries
gallery down

# Force rescan of current gallery
gallery rescan

# Preview scan results without starting server
gallery scan

# Clean up orphaned thumbnails
gallery cleanup

# Delete all cache files
gallery delete
```

## Architecture Overview

### Core Components

**bin/gallery.js** - CLI entry point
- Implements all CLI commands using Commander.js
- Spawns bin/server-runner.js as detached background process
- Manages PID files and server-info.json
- Exports functions conditionally when NODE_ENV=test

**bin/server-runner.js** - Background server process
- Runs detached; generates .gallery-cache/ directory structure
- `generateIndexHTML()` creates the entire UI (HTML/CSS/JS) at runtime
- Implements Express server with SSE for real-time updates
- Handles thumbnail generation pipeline (Sharp + optional FFmpeg)
- Implements viewport-aware thumbnail prioritization

**server.js** - Legacy standalone server
- Backward-compatible direct server mode
- Used for development and non-CLI usage
- Most users should use the CLI instead

**macos-tags.js** - macOS Finder tags integration
- Optional feature, requires `tag` CLI tool
- Provides tag reading/writing via child_process
- Gracefully degrades if tag command unavailable

**metadata.js** - Metadata management
- JSON-based metadata storage
- Base64-encoded filenames for cache keys
- Supports tags, descriptions, ratings

### Runtime Directory Structure

When a gallery is started, it creates:
```
/path/to/photos/
├── .gallery-cache/
│   ├── index.html          # Generated by generateIndexHTML()
│   ├── thumbnails/         # Sharp-generated JPEG thumbnails
│   │   ├── <base64>.jpg    # Full 300×300 thumbnails
│   │   └── <base64>-tiny.jpg # Tiny 64×64 previews
│   ├── metadata/           # JSON metadata files
│   ├── gallery.pid         # Server process ID
│   └── server-info.json    # Port and runtime config
└── <user media files>
```

### Key Technical Details

**No Static HTML**: All HTML, CSS, and client-side JavaScript are generated at runtime by `generateIndexHTML()` in bin/server-runner.js. Do not look for template files.

**Thumbnail Generation Pipeline**:
- Two-phase: instant tiny previews (64×64) then full thumbnails (300×300)
- Viewport-aware: prioritizes visible images first
- Uses Sharp for image processing (optional dependency)
- Uses FFmpeg for video frame extraction (optional, falls back to placeholder)
- Configurable via CLI flags: `--max-workers`, `--ffmpeg-timeout`, `--disable-video-thumbs`

**Process Management**:
- Server runs as detached child process
- PID stored in `.gallery-cache/gallery.pid`
- Server info (port, etc.) in `.gallery-cache/server-info.json`
- File watching via chokidar for real-time updates

**Search Functionality**:
- Client-side filtering by filename or folder name
- Real-time filtering as user types (no API overhead)
- Data stored in DOM attributes (`data-filename`, `data-dirname`)
- Keyboard shortcut: Ctrl/Cmd+K to open/close
- Works in combination with heart and tag filters
- Expandable search input with smooth CSS animations

**Caching Strategy**:
- Gallery scans cached for 30 seconds
- Thumbnails cached permanently until source changes
- File watcher invalidates cache automatically
- Manual invalidation via `gallery rescan` or UI button

**SSE (Server-Sent Events)**:
- Real-time thumbnail generation progress
- Events: `request_viewport_items`, `tiny_preview_ready`, `thumbnail_ready`, `global_thumbnail_progress`
- Client reports viewport items via POST /api/viewport-items

## Testing Infrastructure

### Test Requirements
- Jest test framework with jsdom environment
- All tests in `tests/` directory
- 116 tests across 8 test suites (all must pass)
- Test timeout: 10 seconds

### Critical Testing Patterns

**1. Mocking Commander.js (required for CLI imports)**:
```javascript
jest.mock('commander', () => {
  class MockCommand {
    name() { return this; }
    description() { return this; }
    version() { return this; }
    command() { return this; }
    option() { return this; }
    action() { return this; }
    parse() { /* no-op */ }
  }
  return { Command: MockCommand };
});
```

**2. Conditional exports in source files**:
```javascript
// At bottom of bin/gallery.js
if (process.env.NODE_ENV === 'test') {
    module.exports = {
        functionToTest,
        anotherFunction
    };
}
```

**3. Proper mock isolation**:
```javascript
beforeEach(() => {
    jest.resetAllMocks();  // Critical: must come before clearAllMocks
    jest.clearAllMocks();
});
```

**4. Use fs.promises correctly**:
```javascript
const fsPromises = require('fs').promises;
await fsPromises.readFile(...);  // ✓ Correct
await fs.readFile(...);          // ✗ Wrong (callback API)
```

## Development Workflow

### Adding New Features
1. Write tests first (TDD approach)
2. Mock Commander if importing bin/gallery.js
3. Set NODE_ENV=test before importing modules
4. Run `npm test` continuously
5. Export new functions with NODE_ENV check
6. Update this file if architecture changes

### Common Issues
- **Tests fail with permission errors**: Mock filesystem operations
- **Tests pass individually but fail together**: Add `jest.resetAllMocks()` in beforeEach
- **Can't import from bin/gallery.js**: Set `process.env.NODE_ENV = 'test'` first
- **Sharp installation fails**: Gallery still works, but without thumbnail generation

## System Requirements

- **Node.js**: 20.0.0 or higher
- **Optional Dependencies**:
  - Sharp: Image thumbnail generation (falls back gracefully)
  - FFmpeg: Video frame extraction (falls back to placeholder)
  - tag CLI (macOS): Finder tags support (macOS only)

## Important Notes

### Security
- Path traversal protection prevents access outside scan directory
- Only serves files with supported media extensions
- Base64-encoded filenames prevent conflicts

### Optional Dependencies
The application gracefully handles missing optional dependencies:
- **Sharp not available**: Warns user, disables thumbnail generation
- **FFmpeg not available**: Uses placeholder thumbnails for videos
- **tag command not available**: Disables Finder tags features (macOS only)

### Semantic Release
- Uses semantic-release for automated versioning
- Configured in .releaserc.json
- Generates CHANGELOG.md automatically
- Triggered by commit message format (conventional commits)

## API Endpoints

### Primary Endpoints
- `GET /api/gallery` - Returns JSON with all images organized by directory
- `GET /progress` - SSE endpoint for real-time thumbnail progress
- `POST /api/rescan` - Invalidates cache and rescans directory
- `POST /api/viewport-items` - Client reports visible items for prioritization
- `POST /api/pause-thumbnails` - Toggle thumbnail generation pause state
- `GET /image/:path` - Serves full-resolution image
- `GET /static/*` - Serves cached thumbnails and files

### macOS-Specific Endpoints
- `GET /api/macos/tags/:path` - Read Finder tags for file
- `POST /api/macos/tags/:path` - Write Finder tags to file
